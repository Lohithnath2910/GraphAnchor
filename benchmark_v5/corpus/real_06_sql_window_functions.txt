SQL Window Functions and Ordered Data

Window functions are a category of SQL functions that perform calculations across a group of rows while still returning a value for every individual row, unlike GROUP BY, which collapses a group of rows down into a single summary row per group. A window function is called as part of the SELECT list or alongside the ORDER BY clause, but it cannot be called inside a WHERE clause. A window function definition generally has two parts: the function itself, such as RANK, ROW_NUMBER, DENSE_RANK, SUM, or AVG, and the window the function operates over. The window can optionally be divided into partitions, which groups rows together for the purpose of the calculation, for example by department, and it can optionally be ordered within each partition, which some ranking functions require.

RANK() assigns a rank to each row based on the specified ordering. When two or more rows are tied, RANK() gives them the same rank, but it then skips the rank number or numbers that would otherwise have followed, so the next distinct value jumps ahead. If no partitioning is applied, SQL does not form separate groups and instead ranks every row together as one group.

DENSE_RANK() is similar to RANK() in that the highest value gets rank 1 and tied rows receive the same rank, but it differs in one important way: it does not skip any rank numbers after a tie. This is why it is called "dense": the sequence of rank numbers stays continuous with no gaps, whereas RANK() leaves gaps wherever ties occurred.

NTILE() divides the rows within a window into a specified number of roughly equal groups, or buckets, and assigns each row a bucket number. When partitioning is used, employees are first grouped by department, and then, within each department, sorted and divided into the requested number of buckets; if a department has fewer employees than the number of buckets, some buckets end up empty. When no partitioning is used, all rows are treated as one single group and divided into buckets as evenly as SQL can manage, with any leftover rows distributed across the earliest buckets.

CUME_DIST(), or cumulative distribution, is a window function that reports the percentage of rows in a partition whose value is less than or equal to the current row's value. The result always falls between zero, which is never actually returned, and one, which is always returned for the highest value in a partition. Dividing the data by department means each department's cumulative distribution is calculated independently of the others.

ROW_NUMBER() assigns a unique, strictly increasing sequential number to each row within a partition, with no repeats even when values tie. This is the key difference among the three sequencing functions: ROW_NUMBER() always gives unique numbers, RANK() repeats a number for ties and then skips ahead, and DENSE_RANK() repeats a number for ties without skipping ahead.

AVG(), when combined with a window instead of a GROUP BY, becomes a window function that calculates an average without collapsing the rows into a single output row; it displays the same average on every row within a partition instead. Adding an ORDER BY clause alongside the partition changes the calculation into a running, or moving, average, where the average is computed only from the first row up to the current row within each department, rather than across the whole partition.

SUM(), used the same way, becomes a window function that calculates a total without combining rows. Used with just a partition, it reports the total of a given column for each department. Used with a partition and an ordering together, it becomes a running, or moving, total that accumulates row by row within each department.

COUNT(), when used as a window function, counts rows without collapsing them into a single summary row, so every employee can still see how many employees are in their own department. Adding an ordering turns it into a running count that increases row by row within the partition instead of showing the final total on every row.

MIN() and MAX(), used as window functions together, can report the highest and the lowest value, such as salary, within each department on every row, without grouping the rows together the way a plain aggregate query would.

LEAD() is a window function that lets a query look ahead to the value in a future row without needing a self-join. It takes the column to look ahead on, how many rows ahead to look, which defaults to one row, and a default value to return if there is no next row, which itself defaults to being empty. LEAD() is often used to compare an employee's value, such as salary, with the next employee's value once the rows have been sorted within a partition, and the offset can be changed to look further ahead than just one row.

FIRST_VALUE() returns the first value in an ordered group of rows, for example the highest salary in a department once the department's employees are sorted from highest to lowest, and that same first value is then shown on every row in that ordered group.

LAST_VALUE() returns the last value in an ordered group of rows, but by default it only considers the rows from the start of the partition up to the current row, rather than the entire partition, so the "last value" it reports can change as the current row moves further down the ordered list.

LAG() is the mirror image of LEAD(): instead of looking forward to a future row, it looks backward to a previous row. It takes the same kind of arguments, the column to look at, how many rows back to go, defaulting to one, and a default value to use when there is no earlier row. Sorted by ascending salary within a department, LAG() lets each employee's row show the salary of the employee immediately before them in that ordering.

Beyond ranking and aggregation, SQL also provides tools for preparing data for analysis by cleaning, updating, and filtering out redundant or unwanted records. The CASE WHEN clause works like a nested IF-THEN-ELSE statement: it steps through a series of conditions in order and returns a value corresponding to the first condition that is met. NULLIF takes two parameters and returns an empty result if the first parameter equals the second, otherwise it simply returns the first parameter unchanged. LEAST and GREATEST are two frequently used functions for data cleaning that return, respectively, the smallest and the largest value out of a given set of elements, for example to enforce a minimum or maximum allowed value in a column. DISTINCT returns only the distinct, non-repeating values found in a specified column.
